# 微信后台「用户隐私保护指引」填写清单

> 本文件是**填写对照表**，不是配置项。真正生效的是发布流程中弹出的微信官方隐私指引表单（`setprivacysetting`）。
> 表单未声明的信息类型，对应的隐私接口在真机上会调用失败，所以必须按代码实际情况逐项申报。

## 一、代码实际触发的隐私能力

| 代码调用 | 对应 `privacy_key` | 用途文案（建议原文照抄） | 是否必须 |
|---|---|---|---|
| `wx.chooseMedia`（`pages/upload/upload.js`，相册多选 / 拍照） | `Album`（选中的照片或视频信息） | `拍摄或从相册选择要归档的单据照片` | ✅ 必须 |

说明：

- `wx.chooseMedia` 在微信官方「隐私接口 ↔ 处理的信息」映射里归 `Album`。若发布表单对"拍照"单独提示摄像头相关项，按表单实际提示补充勾选，**但不要为了保险把无关能力全部勾上**——每一个额外声明都是审核时需要解释的隐私主张。
- 用途文案写的是"目的"，小程序会渲染成「为了{文案}」。不要以「为了 / 用于」开头，也不要写「获取相册权限」这种复述能力的话。

## 二、代码中确认**没有**使用（不要申报）

- 无 `wx.getLocation` / `wx.chooseLocation` → 不申报 `Location` / `ChooseLocation`
- 无头像昵称组件、无 `getPhoneNumber` → 不申报 `UserInfo` / `PhoneNumber`
- 无 `wx.chooseMessageFile`、无剪贴板、无通讯录、无日历、无蓝牙、无微信运动 → 不申报对应项
- 无 `wx.chooseInvoice` / `wx.chooseAddress` → 不申报 `Invoice` / `Address`
- 不采集身份证号、手机号、邮箱字段 → 不申报 `EXIDNumber` / `PhoneNumber` / `Email`
- 记录是**仅本人可见的私人档案**，不是公开发布内容 → 不按 `EXUserPublishContent` 申报
- 本版未引入任何第三方统计、追踪、广告 SDK（广告为微信官方 `<ad>` 组件，属平台能力）

## 三、自行收集的信息（表单「其他信息」或自定义项按实际填写）

用户主动填写与保存：拍照日期、自定义关键字、类型、备注，以及单据照片本身。照片可能包含姓名等个人敏感信息，隐私说明已提示用户自行判断并遮挡。

这些信息**全部只写在本机**，不经过服务器、不与第三方共享、不用于广告定向。单机版无需申报"数据共享给第三方"。

## 四、逐项核对（提交前）

1. 相册 / 摄像头权限是否只在用户点击「拍照 / 相册」时触发 —— 是（不在启动时申请）。
2. 首次保存前是否明示告知并取得同意 —— 是（`pages/upload/upload.js` 的 `wx.showModal`）。
3. 是否有可随时访问的完整隐私政策页 —— 是（`pages/privacy/privacy`）。
4. 是否支持删除单条与清空全部 —— 是（详情页 / 我的页，均二次确认）。
5. 是否声明数据仅存本机、换机或卸载不可恢复 —— 是。
6. 是否声明未来接入广告时健康数据不用于定向 —— 是（隐私页第四节）。
7. 发布表单中「第三方 SDK」一栏按**实际**填写：本版无；若以后接入云服务 SDK，需重新评估并如实申报。
8. 真机验证：H5 预览无法验证 `wx.chooseMedia` 与隐私授权弹窗，必须在微信内打开体验版实测。

## 五、常见驳回原因

- 名称 / 简介 / 页面出现"诊断、治疗、用药、疗效、推荐医院、提高治愈率"等医疗表述 → 改回"单据整理、归档、检索"口径。
- 隐私指引里声明的能力与代码实际调用不一致（多报或少报）。
- 涉及敏感个人信息却未提供可删除 / 可清空入口，或没有独立隐私政策页。
- 声称"仅本地存储"却实际调用了第三方统计或上传接口。
